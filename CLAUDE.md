# ContentRadar — Платформа аналитики контента для товарного бизнеса
 
## Миссия проекта
Заменить ручной Excel + сломанную 5meta на красивый автоматический дашборд, который собирает статистику роликов со всех соцсетей и показывает эффективность креаторов и товаров. Точные данные, современный UI, обновление раз в сутки.
 
## Контекст бизнеса
- Целевая аудитория: селлеры на Wildberries, которые работают с "контент-заводом" (3-40 креаторов, снимающих ролики для продвижения товаров)
- Текущий процесс клиента: управляющий вручную раз в неделю сводит данные в 3 Excel-таблицы
- Конкуренты: 5meta (кривые данные, ужасный UI), Wildbox (блогерская аналитика поверхностная), LiveDune (нет привязки к товарам). Прямой замены нет.
- Первый клиент уже есть. У него 3 креатора, несколько товаров на WB, публикации на 5+ платформах
- Ценовой якорь: 10-15К руб/мес за SaaS, до 30К за кастом
 
## Структура данных (из реальных Excel-таблиц клиента)
 
### Сущности:
1. **Креатор** — человек, который снимает ролики (пример: Полина, Катя Ежикова, Катя ДДД)
2. **Товар** — продукт на WB с артикулом (пример: "Стич 596897327", "Кошка 248332917")
3. **Ролик** — одна единица контента. Связь: один ролик = один товар, один креатор, одна платформа
4. **Платформа** — TikTok, YouTube, Instagram Reels, Likee, Pinterest
 
### Таблица 1: Еженедельная сводка по креатору
- Строки: платформа (TikTok, YouTube, Likee, Pinterest, Instagram)
- Колонки: просмотры, % изменения к прошлой неделе, количество роликов
- Группировка по креатору и неделе
- Итого: сумма просмотров за неделю
 
### Таблица 2: Просмотры по товарам в разрезе платформ
- Строки: товар (название + артикул WB)
- Колонки: TikTok просмотры, Likee просмотры, YouTube просмотры, Instagram просмотры, Pinterest просмотры
- Группировка по креатору
 
### Таблица 3: Распределение роликов по товарам и креаторам
- Строки: товар (название + артикул WB)
- Колонки: артикул WB, всего роликов на артикул, количество роликов от каждого креатора
 
### Метрики которые отслеживает клиент:
- Просмотры (главная метрика)
- Репосты и сохранения
- Лайки, комменты
- Количество роликов в день (KPI: ~5 роликов/день на креатора)
- Еженедельная динамика (% к прошлой неделе)
 
## Технические требования
 
### Стек:
- **Frontend**: Next.js 14+ (App Router), React, TypeScript, Tailwind CSS, Recharts для графиков
- **Backend**: Next.js API Routes
- **База данных**: PostgreSQL (Supabase или Neon)
- **Парсинг**: Python-скрипты для сбора данных из соцсетей. Cron раз в сутки.
- **Деплой**: Vercel (фронт) + Railway/Fly.io (парсер)
- **Auth**: NextAuth.js или Clerk
 
### Архитектура:
```
[Cron каждые 24ч]
     |
[Python Scraper] → собирает метрики по ссылкам роликов из всех платформ
     |
[PostgreSQL] ← хранит все данные
     |
[Next.js API] → отдаёт данные на фронт
     |
[React Dashboard] → красивый UI с графиками
```
 
### Схема БД (стартовая):
```sql
-- Пользователи (селлеры)
users (id, email, name, created_at)
 
-- Креаторы
creators (id, user_id, name, avatar_url, created_at)
 
-- Товары
products (id, user_id, name, wb_article, created_at)
 
-- Ролики
videos (
  id, user_id, creator_id, product_id,
  platform (enum: tiktok, youtube, instagram, likee, pinterest),
  url,
  published_at,
  created_at
)
 
-- Метрики (снимаются ежедневно)
video_metrics (
  id, video_id,
  views, likes, comments, shares, saves,
  scraped_at (timestamp когда собрали данные)
)
```
 
## Экраны MVP (приоритет разработки)
 
### Экран 1: Главный дашборд
- Общие просмотры за выбранный период
- Разбивка по платформам (pie chart или bar chart)
- График динамики просмотров по дням
- Топ-5 роликов за период
- Сравнение с прошлым периодом (% изменения)
 
### Экран 2: Креаторы
- Таблица креаторов: имя, просмотры за период, кол-во роликов, средние просмотры на ролик, % изменения
- Клик на креатора → детальная страница с разбивкой по платформам и товарам
- Выполнение KPI (план роликов в день)
 
### Экран 3: Товары
- Таблица товаров: название, артикул WB, просмотры за период, кол-во роликов, разбивка по платформам
- Клик на товар → все ролики по этому товару с метриками
 
### Экран 4: Ролики (таблица всех роликов)
- Фильтры: по креатору, товару, платформе, дате
- Сортировка: по просмотрам, дате, EV%
- Ссылка на оригинал ролика
 
### Экран 5: Настройки
- Добавить/удалить креатора
- Добавить/удалить товар (название + артикул WB)
- Добавить ролик (ссылка, выбрать креатора и товар)
- Импорт из CSV
 
## UI/UX требования
- Тёмная тема по умолчанию
- Современный дизайн уровня Linear/Vercel Dashboard
- Шрифт: Geist Sans + Geist Mono
- Графики: Recharts с анимациями, чистые, без визуального мусора
- Таблицы: сортировка, фильтры, пагинация
- Responsive: работает на десктопе и планшете
- Быстрый: страницы грузятся < 1 сек
 
## Правила разработки
- TypeScript strict mode везде
- Используй Server Components где возможно
- API: валидация через Zod
- Используй drizzle-orm для работы с БД
- Каждый коммит = рабочее состояние приложения
- Сначала schema БД → потом API → потом UI
- Тесты не нужны на MVP, скорость важнее
 
## Порядок реализации
 
### Фаза 1: Фундамент (день 1-2)
1. Инициализация Next.js + TypeScript + Tailwind
2. Настройка PostgreSQL (Supabase/Neon)
3. Создание схемы БД (миграции через drizzle-kit)
4. Seed-данные из реальных Excel-таблиц клиента
5. Базовый layout (sidebar navigation, header)
 
### Фаза 2: API + Экраны (день 3-5)
1. API endpoints: /api/dashboard, /api/creators, /api/products, /api/videos
2. Главный дашборд с графиками
3. Страница креаторов
4. Страница товаров
5. Таблица роликов с фильтрами
 
### Фаза 3: Парсер (день 5-7)
1. Python-скрипт парсинга TikTok (приоритет — самая важная платформа)
2. Парсинг YouTube
3. Парсинг Instagram
4. Парсинг Likee
5. Cron-задача для ежедневного обновления
6. Логирование ошибок парсинга
 
### Фаза 4: Настройки + Onboarding (день 7-8)
1. Страница настроек (CRUD креаторов, товаров)
2. Добавление роликов (ввод URL)
3. Импорт из CSV
4. Auth (простой — email/password)
 
## Делегирование задач саб-агентам
 
При реализации этого проекта делегируй задачи следующим саб-агентам:
 
- Используй `db-architect` агента для проектирования и миграций схемы БД, написания SQL-запросов
- Используй `frontend-builder` агента для создания React-компонентов и страниц дашборда
- Используй `scraper-engineer` агента для написания парсеров соцсетей
- Используй `code-reviewer` агента для ревью кода перед коммитом
 
Когда задача затрагивает несколько доменов (например, новый экран = API + UI + схема), запускай агентов параллельно по их доменам.
